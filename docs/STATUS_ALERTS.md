# 平台接口状态错误告警

2026-10-13 接入，沿用 Banyue 的飞书应用令牌和 interactive 红色卡片流程，发送到现有配置群。通过 `.local/env/.env` 中 `FEISHU_STATUS_ALERTS_ENABLED=true` 启用；应用凭据仍使用原来的三个 FEISHU 配置，不写入代码或日志。

## 告警范围

- 全部已注册平台的互动、评论接口；同步、批量任务共用采集服务入口。
- 已支持作者采集平台的作品列表和作品详情；包括后台任务的分页、详情请求。
- API 返回 5xx、批量任务超时或异常、作者后台任务程序/存储异常。
- 采集接口的 502 由采集服务按实际原因分类，不仅凭 HTTP 状态发卡片，避免内容不可用触发误报。
- 明确的登录失效、会话拒绝、验证码/风控、HTTP 401/403/429 等限制、上游 5xx、连接失败/超时、非 JSON 响应和程序异常。
- 已识别的业务状态码会分类；不能仅凭 `coverage=failed/blocked` 推断账号掉线。无法确定的缺数据结果不告警。

不通知：赞藏分享等字段为 null、计数为 0、空评论、数据不完整、内容不存在/已删除/不公开、目标或分页参数不合法、不支持的采集能力、正常结束的分页。`sample_failed` 仅记录小红书样例数据不完整，不发送卡片。

告警在一次采集的重试/回退结束后按最终错误触发；中间请求失败但最终取得正常结果不通知。接口缓存命中不再次入队。内部异常分类使用私有字段，不改变公开响应格式。

## 调度和去重

其他平台在实际业务请求发生错误时触发，没有新增对所有平台的定时采集压力。API 进程仅将脱敏错误写入本地 SQLite，飞书发送由独立命令处理，避免等待飞书网络请求。

```
python -m app.manually_execute_script.send_status_alerts
```

cron 每分钟运行一次；使用 `flock` 防止重复投递进程。同平台、同接口、同错误类别在成功发送后 30 分钟内合并。持续存在且仍有新请求的故障，超过窗口后可再次提醒。飞书失败每 5 分钟重试，持久化 UUID 作为消息去重键；仅收到消息 ID 才标记成功。存储故障记录本地错误日志，不改变采集结果。

小红书保留独立的每 30 分钟真实样例检查、每分钟本机进程状态检查，以及同一次会话故障只通知一次的规则。互动/评论的登录失效和风控由这个常驻监测通知，避免每个业务请求重复发卡片；小红书作者接口使用独立采集路径，仍由通用告警处理。账号异常时继续暂停样例上游请求。本次未改变单 IP 限速，也未重启浏览器。

## 运维查看

- `/api/v1/health` 的 `status_alerts_enabled` 表示当前 API 的配置开关。
- `.local/status-alerts/alerts.sqlite3` 的 `alerts` 表保存最近各类故障及投递状态：`report`、`occurrences`、`incident_id`、`message_id`、`sent_at`、`attempts`、`next_attempt`、`delivery_error`。这是按错误类别维护的发送队列，不是历史明细库。
- `.local/status-alerts/cron.log` 保存通用投递任务摘要。
- 小红书使用原有 `.local/xhs-monitor/status.json`、`probes.jsonl`、`cron.log`。
- 凭据、完整请求 URL、Cookie 不写入通用卡片；HTTP 服务错误附请求 ID 和路由模板。

此机制依赖业务进程或小红书监测能记录错误；整台服务器、cron 或飞书本身完全不可用时，无法保证即时送达。其他平台没有业务请求时不主动验证登录状态。

## 验证方式

使用模拟上游和模拟飞书，验证全平台注册入口、明确错误/缺数据边界、异常类型跨结果转换、缓存不重复入队、跨实例并发去重、发送失败重试、API 5xx、作者采集以及批量任务取消引起的超时。未向真实平台制造登录失效/风控，也未向群里批量发送测试故障。
