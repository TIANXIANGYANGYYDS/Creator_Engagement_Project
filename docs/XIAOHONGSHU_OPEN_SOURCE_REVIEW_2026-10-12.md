# 小红书公开实现对照与移动页补数（2026-10-12）

## 本轮新增能力

此前桌面详情互动全为空字符串的部分笔记，现在可以取得移动分享页明确返回的评论总数。
这里的数值 0 来自平台响应，不是把点赞、收藏、分享的空字符串转换成 0。
这些笔记的其他计数仍可能未知，不能将“至少取得一个互动字段”解释为所有字段完整。

线上输入仍使用 `.local/banyue.public_opinion_data.json` 中的原始 URL，账号和本机直连策略不变。
本轮没有点赞、收藏、发布、发送评论或采购第三方接口。

## 新路径的证据

使用移动 Safari UA、同一已授权 Cookie、同一笔记 token，请求 `/discovery/item/{note_id}`。
页面的 `window.__SETUP_SERVER_STATE__.LAUNCHER_SSR_STORE_PAGE_DATA` 下同时包含：

- `noteData.noteId`：用来核对目标笔记。
- `noteData.interactInfo`：点赞、收藏、分享及格式化评论数，可能仍为空字符串。
- `commentData.commentCount`：独立评论总数，为数值。
- `commentData.commentCountL1`、`comments`、`hasMore`、`time`：一级总数、预览正文、分页状态及返回时间。

移动页预览只有 5 条，不能用预览条数代替总数；有些计数也会随时间自然增长。
最后一条在更早的测试中曾为空值，本次已出现赞、藏、分享，不能把这种自然变化归因于新解析器。

进一步追踪官方 `main.0c3bdc1.js` 与 `vendor.b65b050.js`：移动页通过
`/api/sns/h5/v1/comment/page` 获取评论数据；失败分支返回 null，没有把失败填成 0。

与页面内的数据一致。相应完整响应保存在 `h5-api-*.json`，没有将 HTTP 成功本身当作有数据。

## 实现与验证规则

桌面 SSR 已有至少一个互动数值时保持原流程；目标存在、互动全空且有访问 token 时，
增加一次移动详情请求。解析器严格核对目标 ID，读取明确的数值字段，并核验主评论总数、
列表、分页标志及返回时间。缺字段、错误目标、数值与列表矛盾或访问限制仍返回未知/失败。
点赞、收藏和分享没有数值时保持 null。

评论正文继续使用已有的主评论与回复分页；移动预览不会冒充完整正文。
移动页请求受同一个客户端的直连限速约束；受到 461 等限制后停止重试。

来源索引 149 的原始笔记 ID 调用 H5 feed，不提供 token，第一次返回 HTTP 461、业务码
300017、消息“访问链接异常”，没有数据。该路径立即停止，没有切换签名重试，也未接入生产。
不能由该结果断言 IP 被封或账号掉线；19:48:50 的官方 user/me 核验仍为 guest=false。
