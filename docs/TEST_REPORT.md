## 请求隔离与资源保护实测

- 互动量和评论接口分别执行上游流程、分别缓存；只有相同接口、URL、媒体和页码的重复请求
  才复用 120 秒缓存，同时到达的完全相同请求只运行一个上游任务。
- 一次业务流程内连续 GET/POST 可共用一个代理租约，单元测试确认只取得和归还一个代理
  IP；这些 HTTP 调用仍按各自的上游请求数量记录。
- 全服务采集并发默认 4，浏览器并发默认 2，51 代理池由 4 降为 2；缓存最多 1000 项。
- 快手互动量和评论联合诊断 20.17 秒、峰值 RSS 411096 KB；其中包含页面导航、详情和评论
  等多个请求，不能记为一次请求。
- 抖音匿名纯协议联合诊断 1.93 秒、峰值 RSS 64680 KB，返回点赞 20303、评论总数 2909、
  首屏 20 条及下一游标 20；其中包含预热、访客初始化、详情和评论等多个请求。

完整成本公式和低内存参数见 [`COST_AND_CAPACITY.md`](COST_AND_CAPACITY.md)。

## 本轮修复

1. 好看视频新增纯协议目标页 SSR 解析，补齐精确播放、点赞和评论数，并校验目标 `vid`。
2. 微博 `hotflow` 后续页跳登录时自动降级匿名 `api/comments/show?page=N`；纯表情评论保留 `img.alt`。
3. 小红书签名路径补齐 `x-xray-traceid/x-mns/xy-direction/x-rap-param`，HTTP 406 时从 `XYS_` 重试 `XYW_`。
4. 公众号新增 `preload_comment_list` 首屏解析；没有预载数据时仍严格遵守原生会话边界。
5. 浏览器评论链路改为先打开评论区，再滚动页面与弹层内部容器，避免只滚动外层页面而不
   触发深分页请求。
6. 本地登录命令扩展到八个平台，支持 `--url` 直接打开目标内容页；不接收账号密码或
   Cookie，状态只保存在 Git 忽略目录。
7. 浏览器兜底也严格区分互动量与评论：互动量请求不再点击或滚动评论区，减少无关请求和
   风控触发面。
8. 头条浏览器 SSR 只接受目标 `work_id` 对应的 document，推荐文章或 iframe 的计数不会
   再覆盖目标互动量。
9. 全量测试从 79 增至 85；八个平台 16 条首屏真实请求重新执行，7 个原样例通过，小红书
   失效样例换成当前公开笔记后互动量和首屏评论通过。
10. 外部互动/评论接口及上游流程保持分开，并加入按接口参数隔离的 TTL/LRU 缓存、相同
    请求任务合并、全局采集上限和浏览器上限。
11. 同一个业务流程的协议请求使用一个惰性代理租约，但 GET/POST 仍分别计数；纯浏览器
    平台不会先空耗协议 IP。
12. 抖音新增第一方访客 `ttwid` 初始化、随机 `msToken` 和纯 Python `a_bogus`，详情和
    评论均通过真实匿名请求验收；调用方 Cookie 与浏览器仅作兼容/风控兜底。
13. 微博协议路径会复用本地 Profile Cookie、XSRF 和 `max_id_type`，有会话时可继续深分页。
14. 全量自动化现为 100 项，并重新通过 Ruff、`compileall` 和 `git diff --check`。

## 仍需外部条件的边界

- 公众号样例由作者关闭评论，无法用任何账号生成不存在的评论；开启评论的文章仍可能需要
  手机微信文章短时会话。
- 小红书游客态只验证首屏，深分页需要调用方自己的有效会话和 `xsec_token`。
- 微博匿名降级已覆盖本轮样例第 2 页；更深页仍可能 `ok=-100`，IP 池不能替代平台权限。
- 抖音已转为匿名签名协议，签名或访客规则变化时仍可能空包并进入浏览器兜底；头条部分
  计数仍受 SSR/挑战影响。
