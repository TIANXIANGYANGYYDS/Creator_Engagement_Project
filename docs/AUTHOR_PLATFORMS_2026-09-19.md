# 作者内容采集 v5 实施与验收

> 历史报告：本版允许账号会话，已被后续“无真实账号”要求取代。当前配置及无账号实测以 [v6 仅访客验收](AUTHOR_GUEST_2026-09-19.md) 为准；下方账号操作不适用于当前作者流程。

2026-09-19，本轮在 v4 抖音实现之上完善其他五个平台。业务输入仍为 `author_id`、`media_name`，详情范围为公开视频标题/简介/链接及文章正文。没有新增作品总量限制。

## 已实施

- 新增作者专用的保存会话读取及快手、微博、B 站、头条 Cookie 配置。HTTP 按域名、路径和有效期筛选保存的 Cookie，浏览器恢复对应平台的 Cookie/localStorage。账号凭据与其他平台、互动采集配置隔离；已有抖音专用会话路径保持不变。
- B 站依次遍历视频投稿、专栏和动态，游标记录当前来源及页码。复用项目已有 WBI 签名，访客设备 ID 在当前代理出口重新初始化。旧动态游标可继续使用，作品 ID 由任务存储去重。
- 微博增加账号桌面时间线及长正文路径。移动时间线即使返回 `ok=1`，只要内容是登录提示，就报告需恢复会话；不再误报空账号或列表结束。重复页也不能作为正常分页继续。
- 快手增加 GraphQL 列表回退，保留 REST 和移动详情。来源作品可以证明数字作者 ID 与主页 ID 的对应关系，在线核验后存入 MongoDB，每次新采集重新读取来源作品核验。
- 小红书增加带签名和会话的 feed 正文接口，接口失败后尝试页面正文，保留列表的 xsec_token 和作者校验，兼容两种来源的字段命名。
- 头条详情识别真正的登录页，避免将页面中的登录协议误作文章。浏览器通用接口新增 20 秒请求超时，外层仍有 120 秒页超时；明确要求登录的失败保留供恢复会话后续跑。

接口形态参考上游 [MediaCrawler B 站客户端](https://github.com/NanmiCoder/MediaCrawler/blob/main/media_platform/bilibili/client.py)、[快手客户端](https://github.com/NanmiCoder/MediaCrawler/blob/main/media_platform/kuaishou/client.py) 和 [小红书客户端](https://github.com/NanmiCoder/MediaCrawler/blob/main/media_platform/xhs/client.py)。使用本项目既有签名依赖及自行实现的最小适配，没有引入整个上游项目。
