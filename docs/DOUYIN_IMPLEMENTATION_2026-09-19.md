抖音作者采集实现与验收，2026-09-19。

> 历史 v4 报告：下方实网结果使用了配置中的账号 Cookie，不能作为无账号采集能力证明。当前仅访客版本及其限制见 [v6 验收](AUTHOR_GUEST_2026-09-19.md)。

本次将调研中的签名、会话和身份核验接入现有作者 API。入参仍为 author_id、media_name；不限制作者数量、作者作品总数或代理使用总数。五页是本次样本验收范围，生产任务继续读取直到平台明确结束或返回错误。

实现改动：

- 配置好的抖音作者会话走协议请求，签名来自固定版本 Evil0ctal 的 Apache-2.0 实现，源码及许可记录在 third_party/douyin_download_api。SM3 使用已有 OpenSSL，无新增运行依赖。旧互动接口的签名流程未切换。
- 新增 DOUYIN_AUTHOR_SESSION_MODE / DOUYIN_AUTHOR_COOKIE，只影响抖音作者采集。使用已有会话的访客参数，避免跨会话混用 token；传输 UA 与 curl_cffi 的 Chrome 124 配置一致。
- 浏览器兜底分别检查访客标识和 SDK 请求签名是否就绪；原生签名与浏览器签名失败都保留明确错误，不把空包视作空账号。
- 作者映射持久保存到 author_identities。首次解析精确匹配 uid / unique_id / short_id；后续核验 sec_uid 归属。跨代理保持本次任务的已核验映射；新任务重新检查主页，必要时检查已核验的来源作品。映射过期含义是平台身份核验不符，不依靠永久信任旧昵称。
- 新增输入文件映射导入脚本，能用用户已经提供的公开作品链接解决部分账号没有进入搜索结果的问题。没有新增请求参数。
- 普通网络失败换出口后继续协议请求；有效搜索中的身份不匹配不淘汰健康代理。所有签名及 Cookie 保留在传输层，不加入 API 结果或日志。
