# 三平台原始 URL 互动采集修复与实测（2026-09-20）

验收输入为 `.local/top20_platform_data.json` 中的原始 `url + media_name`，调用方无需补参数或修改链接。目标是尽量返回真实互动字段，允许只有评论计数。当前结论：完成了链接兼容与评论计数提取修复，但本次 30 条原始样例仍没有取得互动值，尚未达到业务验收目标。

## 已实现并部署

- 小红书同时识别 `/discovery/item/{id}` 与 `/explore/{id}`，内部请求网页详情路径，保留已有 token、source 等查询参数。原始样例不再因解析不出作品 ID 而返回 422。
- 公众号原始 HTTP URL 内部升级为 HTTPS 请求，保留查询参数，批量响应保留调用方 URL。
- 公众号页面只提供正数的 `preload_comment_total_cnt` / `elected_comment_total_cnt` 时，互动接口也提取评论计数。该值是精选评论口径，不等同于全部投稿留言。明确的 `comment_count` 优先；零值预载占位不作为真实零评论；不以首屏评论数组长度充当总数。
- 原有 API 已支持任意一个真实互动字段构成成功，其他字段保持 `null`。单项用 `data.comments`，批量用 `result.total_comments`。

上述代码已经应用到 8200 服务。切换前互动与作者活动任务均为 0，配置未改动，健康检查正常。发布目录：`.local/releases/20260920-150653-interaction-url-compat`；新进程 PID 3109179。

## 额外获取尝试

**小红书**：测试原始 discovery、网页 explore、移动端分享参数、已配置 Cookie、签名 feed 请求、评论接口、浏览器原始页及按作品 ID 搜索。浏览器原始页和 explore 页进入 404；初始状态为 `loggedIn=false`，搜索页提示登录后查看结果。Cookie 被配置和注入不等于它当前构成有效登录态。带 `x-rap-param` 的签名 feed 另外更换代理试了 8 次，均在代理传输层失败；这些失败不能用于证明签名正确或错误，也不能证明服务端一定不允许无 token 请求。

**公众号**：另取 20 条样例，使用 HTTPS 和移动浏览器请求头测试；11 条验证码，9 条网络失败，未发现正文或可提取计数。浏览器进入相同的访问验证码地址，当前页面未加载可操作的验证控件。本次没有命中预载评论计数的真实样例；新增计数分支通过构造响应的回归测试验证，不能算作真实平台采集成功。

**视频号**：直接访问原始客户端跳转页，页面调用 WeixinJSBridge 打开客户端，没有互动计数。将 feedID 原值和去除 `export/` 前缀后的值送入公开预览接口均没有返回 feedInfo，其中响应为“此内容暂时无法播放”；增加 encryptedObjectId 的变体也没有取得数据。另参照公开项目尝试元宝链接解析入口，两次均 HTTP 401；没有配置该服务账号。没有把未经验证的变体接入生产并增加无效重试。
